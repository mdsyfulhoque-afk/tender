# ART-110 — TenderOS v1.1 Product Requirements Document
**Version:** v1.1-draft | **Date:** 2026-10-09 | **Status:** REVIEW_READY, not approved for implementation
**Owner:** Founder | **Product:** TenderOS — Bid Decision Intelligence
**Decision gate:** Founder must approve scope and architectural choices before agent writes to the main application.

## 1. Mission and customer problem
Help consulting companies and other suppliers decide whether to commit scarce time and money to a tender by exposing mandatory eligibility, traceable organizational evidence, disqualification risks, ambiguities, deadline obligations, and next actions. An AI-native service executes bounded analysis tasks; qualified humans verify source interpretations, evidence and final BID/NO-BID/HOLD decisions.

**Primary pilot users:** Bangladesh consultancy / development advisory companies preparing RFP/EOI submissions; secondarily contractors and specialized service firms once validated. **Paid offer hypothesis:** 48-hour expert-reviewed readiness diagnostic, subject to real paid customer testing. The system complements Bangladesh e-GP and donor portals, not replaces their submission functions.

## 2. Governing truth and operating laws
Tender source and official documents > human-reviewed source-linked requirements > verified company evidence > human commercial judgment > AI/derived summaries. The AI may suggest candidate claims but never determines legal eligibility on its own. Mandatory NOT_HELD blocks readiness; mandatory UNKNOWN, PARTIAL, unreviewed or insufficient proof leaves it unresolved. Unclassified requirements remain unresolved. BID can be recorded only after current sources, amendments, mandatory evidence and reviewer signoff pass. An approval becomes stale upon any relevant source/evidence change. No pseudo-statistical win probabilities. Confidential documents remain local until owner approves a specific external processor/provider and privacy arrangement.

## 3. Release boundaries
**MUST for agentic vertical slice:** Accept a real PDF tender and addenda, generate candidate source spans, AI-extract structured requirements, let a human correct/classify, associate organizational evidence, AI-propose evidence relevance, independently check citations, evaluate compliance deterministically, revoke stale approvals, allow named and authorized human decision, export traceable editable matrix, record model/tool costs, and recover from failures.

**MUST for agentic development:** Real autonomous sub-agents (not personas) independently inspect and modify assigned files within task-bound scopes with separate run IDs, tool logs and independent QA. No development changes without a delegated agent receipt and passing review.

**SHOULD later:** Bangla/English OCR/layout, hybrid retrieval, amendments-diff workflow, team work queue, read-only client view, rule pack per procurement method, structured commercial diagnostic.

**DEFER until paid repeat:** Automatic portal discovery, proposal writing, bid submission, autonomous client emails, CRM, subscription billing, marketplaces, financing.

## 4. End-to-end use case
1. Analyst creates assessment and registers source inventory: notice/RFP/eligibility schedules/annexes/addenda with hashes, languages and publication dates.
2. Source Processing Agent extracts PDF text; scanned or poorly rendered source returns `NEEDS_OCR` / `NEEDS_MANUAL_REVIEW`, not invented text.
3. Requirement Analyst (model-powered) emits candidate requirement objects with source IDs, page range, **verbatim short quotation**, normalized requirement, category, and uncertainty. Each object must resolve against source spans.
4. Human checks every material/mandatory condition and attests source coverage; cannot certify the full source merely by checking AI candidates.
5. Evidence Analyst (model-powered) retrieves candidate company documents within same organization and produces specific support mapping, alternative interpretations and gaps. Does NOT mark evidence independently verified.
6. Independent Verification Agent checks exact source quotes, issuer/document reference, eligibility period, contradicting proof and whether document supports the specific requirement. Its result is REVIEW_REQUIRED until a human confirms.
7. Deterministic rule engine produces BLOCKED / UNRESOLVED / READY_FOR_HUMAN_DECISION and prioritized actions. Optional items may be acknowledged rather than blocking readiness, subject to domain policy.
8. Human reviewer records BID/NO-BID/HOLD, rationale, versioned snapshot, identity, source-set fingerprint. New addenda or changes invalidate *current* decisions.
9. Export service produces DOCX/XLSX/CSV report and immutable audit metadata. Pilot metrics track money actually collected, time, missed risks and outcomes.

## 6. Minimum autonomous production workflow architecture
- **Local core:** FastAPI domain API, current deterministic engine retained after fixing DEF-001, SQLite for isolated development; later PostgreSQL tenant-safe schema.
- **Model gateway:** pluggable provider interface with local Ollama-compatible model option when available, cloud option explicitly enabled per tenant/data class; Pydantic schema validation.
- **Orchestrator:** durable state machine; start with a bounded Python workflow plus queue only if persistence/restart requirements can be demonstrated. Do not install CrewAI/LangGraph/Temporal by default without evidence they simplify this actual task.
- **AI specialist task contracts:** `requirement_extract`, `evidence_match`, `independent_verify`; tasks have separate agent IDs, model invocations, permitted tools, structured outputs and ownership.
- **Tool boundary:** PDF/source reader, text search (scoped), evidence search (scoped), quote locator, compliance function (read-only), structured review queue. No portal credentials, email-send, arbitrary filesystem read, shell or payment tools in product agents.
- **Human gate:** source completeness, requirement verification, evidence verification, BID/NO-BID/HOLD approval.
- **Audit:** task ID, parent ID, source set fingerprint, model ID, prompt version, input/output hashes, timestamps, token usage/cost, tool calls and failure state (not raw confidential prompts in ordinary logs).

### Task state machine
`CREATED -> WAITING_FOR_SOURCE -> READY -> RUNNING -> VALIDATING -> WAITING_FOR_HUMAN -> COMPLETED`, with explicit `FAILED`, `CANCELLED`, `RETRY_WAIT`, `NEEDS_OCR`; only allowed transitions; bounded retries (default pilot design: 2, requires approval), idempotency key per job and source hash. Model suggestion never directly changes `VERIFIED` or `BID`.

### Data objects (versioned target)
`organizations`, `users`, `memberships`, `assessments`, `source_documents`, `source_spans`, `source_set_snapshots`, `requirements`, `requirement_revisions`, `evidence_documents`, `evidence_claims`, `agent_jobs`, `agent_steps`, `tool_invocations`, `human_review_actions`, `decisions`, `audit_events`, `pilot_observations`. All user-visible claims carry source/evidence links, source hash and review status. Approved decisions reference *both* source-set hash and requirement/evidence fingerprint. Avoid unscoped joins and use compositional tenant-safe keys in future RLS migration.

### Model output example (contract, not generated fact)
```json
{"candidate_id":"cand-001","source_document_id":"doc-001","page":4,"verbatim_quote":"At least three comparable assignments","normalized_requirement":"Three comparable assignments are required","category":"experience","mandatory_candidate":true,"confidence_label":"NEEDS_HUMAN_REVIEW","uncertainty_notes":"Time window not specified in this excerpt"}
```
**Validation:** `verbatim_quote` must be locatable in underlying source (normalization rules logged); `mandatory_candidate` is never an approved mandatory flag; array entries with missing source linkage rejected or quarantined.

## 7. Security and privacy acceptance (before external use)
Authenticated principals, role-based permissions, tenant isolation, private encrypted storage, upload quotas and malware checks, parser sandboxing, secret management, testable backups, server-side source access control, CSRF protection for cookie sessions, model egress guard, prompt-injection resistant tool boundaries, vulnerability reviews and red-team PDF tests. A reviewer must not merely type their identity. Never deploy current localhost-only API publicly. Disallow automatic model communication with confidential CVs, financial statements, internal contract certificates or bid strategies until explicit permissions are recorded.

## 8. Performance/evaluation plan
Set up a small **consented and labeled** benchmark (proposed first 10 historical opportunities, including 3+ scanned Bangla/English and at least 3 amendments). Human analysts make a gold list of eligibility requirements, condition type, source span and expected evidence. Compare three arms on *same cases*: (A) human analyst, (B) generic AI + Excel, (C) TenderOS agent workflow + human verification. Capture requirement recall (mandatory weighted), precision, source-link validity, false-ready rate, blocker recall, effort (incl. review/rework), total direct cost, data leakage incidents, turnaround time and decision impact. Acceptance: **zero false-ready on the labeled blocking scenarios**, 100% citation resolvability for published mandatory claims, no cross-tenant access or unapproved egress, agent run receipts for all AI claims. Broader accuracy targets are hypotheses to be set after baseline pilot, not market claims.

## 9. Deployment and commercial validation
Pilot must be executable locally without mandatory paid runtime credentials, compatible with founder's APES baseline. A local model variant may cost significant CPU/GPU time; record energy, processing time and review effort rather than calling it free. Hypothesis: BDT 15,000–25,000 for a scoped 48-hour expert-reviewed diagnostic, not a proven market rate. Record actual invoices/payments, second paid orders, decision changes, discovered risks and generic-AI comparator cost. Do not add subscription infrastructure before willingness to pay and repeat use are demonstrated.

## 10. Delivery plan and no-build gate
- **G0 now — READ_ONLY:** verify files, audit, domain and technical research, PRD, sub-agent contracts. Status REVIEW_READY.
- **G1 — AGENT_RUNTIME:** Work runtime must demonstrate real separate delegated agent invocations with logs, isolated workspaces, allowed tools and output receipts. Otherwise STOP; no code edits.
- **G2 — PRODUCT_SCOPE:** owner reviews PRD, approves an explicit pilot model backend, sensitive-data policy and Phase-1 scope.
- **G3 — ENGINEERING:** delegated agent executes critical DEF-001 fix on separate branch/worktree, independent QA verifies; only then merge to approved codebase.
- **G4 — REAL_AI_VERTICAL_SLICE:** two or more model-backed product specialist tasks + independent review; test with permitted, synthetic/open datasets first.
- **G5 — LIMITED_CLOSED_PILOT:** restrict to supervised consenting testers, record paid evidence, deny unsupported live e-GP workflow claims.
- **G6 — EXPANSION:** based on repeat purchase, privacy review, throughput, and controlled deployment readiness.

A versioned git commit produced by actual delegated coding agent; independent sub-agent reviewer receipt; all existing tests + new edge-case tests passing; valid real-model traces; verified source references; zero false-ready on blocking benchmark; privacy default-deny proven; a human reviewer can correct any AI output and produce an auditable report; regression against current prototype documented; release gate approved.
